1. 概要

ローカルで動かす AI のソフト(サービス)を、ブラウザから起動・停止・切り替えするダッシュボード。GPU を取り合うサービスは、排他グループに入れて、同時に動かさない。ソフトのインストールは利用者が済ませておく前提で、ハブは「起動と管理」だけを担当する。

設計の方針① 依存なし(Python 標準ライブラリだけ・画面もビルド不要) ② 設定はファイル(JSON)で、手でも書ける ③ ハブはファイルを消さない(コマンドを見せるだけ) ④ アプリごとの違いは、アプリのフォルダに閉じ込める(共通の仕組みは、アプリの中身を知らない) ⑤ 状態の保存は最小限(ほとんどメモリ上)
動作環境Linux(/proc、ss、nvidia-smi を使用)/ Python 3(動作確認は 3.14)
起動と停止./start.sh(バックグラウンドで起動し、URL と PID を表示。PID は state_dir/hub.pid、ログは state_dir/hub.log)/ ./stop.sh(ハブにだけ SIGTERM、10 秒待って SIGKILL。サービスは、別のセッションなので、止まらない)。設定の誤りやポートの使用中は、起動前に理由を表示する。PID ファイルは、/proc/<pid>/cmdline に hub.py が含まれるときだけ信用する(別のプロセスを止めない)。--foreground は、前面での起動、--status は状態の確認
自動起動(オプション)./start.sh --install-service で、systemd のユーザーサービス(ExecStart=python3 hub.py、Restart=on-failure、KillMode=process)に登録。登録後は、start.sh / stop.sh が、サービスを対象にする(systemctl --user と同じ。ただし、ExecStart がそのフォルダの hub.py のときだけ。別のフォルダのクローンからは、止めない)
エントリポイントpython3 hub.py または python3 -m patchbay(同じ。hub.py は、薄い入口)。hub.py --info は、スクリプト用に、設定(状態の置き場・host・port・認証の有無)を表示する

2. 全体構成

画面は、2秒ごとに /api/state を読み、モニターは5秒ごとに /api/monitor を読む(新しい点だけ)。サービスの稼働は、ハブが記録した PID と、ポートへの接続の両方で判定する。

10. 主な処理の流れ

10.1 サービスの起動(POST /api/start → core/lifecycle.py)

  1. 検証(同期): プリセットを取得 → 「使う」か確認 → app.build_command でコマンドを組み立てる(モデルやスクリプトの存在も確認)→ app.validate。失敗すると、すぐ HTTP 400。
  2. 操作スレッドを開始(同時に1つだけ。実行中なら「別の操作を実行中です」)。画面には ops の busy と msg で進捗を出す。
  3. 排他(stop_group_of): 同じグループのサービス(と自分自身)を停止(SIGTERM → 最大30秒待つ → SIGKILL)。
  4. 準備(app.prepare): ComfyUI / Forge は、モデルセットの表示用フォルダを作り直し(ComfyUI は yaml、Forge は前回選択の整理と dir_args)、ランチャーのサービスは、git・Python・venv・TCMalloc を確認する。戻り値の Prepared が、ログの先頭の行と、画面に出すセット名を持つ。
  5. 起動(process.spawn): 新しいセッションで Popen(ハブが落ちても、サービスは落ちない)。running.json に記録。
  6. 状態の確認: 画面は2秒ごとに /api/state。service_status が、記録した PID の生存と、ポートへの接続から、「起動中…」→「稼働中」を判定する。同じポートを使う別のサービスが動いていても、混同しない。

10.2 ダウンロード(downloads/engine.py)

  1. inspect: URL が Hugging Face なら、API でファイル一覧を取り、アプリのルールが許す拡張子だけ残す。種別のあるアプリでは、ルールの guess で種別を推定する。
  2. enqueue: ルールの dest が、保存先を決めて、安全確認(safe_dest: モデル置き場の外・許可外の拡張子・既存ファイルを拒否)をする。ルールの job_options が、共有リンクとセットの指定を決める。
  3. ダウンロード用のスレッド(1つ)が順番に処理。.part に書き、続きから再開できる。空き容量を事前に確認。
  4. 完了すると、.part を本来の名前にして、ルールの on_done が、共有リンクとセットへの追加を行う。

10.3 モニター(monitor/sampler.py)

  1. Sampler のスレッドが、5秒ごとに、/proc/stat・/proc/meminfo・/proc/diskstats・nvidia-smi を読み、差分から、使用率や速度を計算する。動いているアプリの固有の指標は、各アプリの stats() から集める。
  2. サンプルを deque(最大 2,160 点=3時間)に追加。ファイルには書かない(ハブの停止でリセット)。
  3. 画面は、モニターのタブを開いている間、since 以降の新しい点だけを取得。モデルの再起動で累計が減ったら、リセットとして扱う。

12. 安全面

リスク現状の対策残る点
任意のコマンドの実行(cmd / extra)雛形の初期設定は 127.0.0.1 のみ。token で API を保護できる設計の判断: token は、補足的な機能で任意(空でも起動する)。LAN 公開で空のままだと、LAN の誰でも実行できる。信頼できる LAN での利用が前提(README に明記)
別のサイトからの操作(CSRF)・DNS リバインディングブラウザ経由で、ハブに「起動コマンドを書いたプリセット」を送り込む攻撃への備え。①Host ヘッダが、IP アドレス・localhost・このPCのホスト名・allowed_hosts のどれかでなければ 403(判定は api/handler.py の host_allowed)。②Origin があれば、Host と同じ場所でなければ 403。③POST は application/json だけ(別サイトの <form> や、事前確認なしのリクエストでは送れない形)なので、それ以外は 415自分で決めた名前や DNS の名前で開くときは、allowed_hosts に書く(README の「別の端末から使う」)
入力の型・形(コマンドへの混入)すべての API 入力を、ルートごとの型の定義(api/routes.py、部品は core/schema.py)で検証してから処理。文字列は制御文字(改行・NUL)と長さを制限。プリセットの項目は、アプリごとの型(preset_fields)で検証。machine.json は、読み込み時と、⚙ からの保存前に検証し、型の誤りは起動を止め、未知のキーは警告(core/machine_schema.py)。コマンドはシェルを通さず、リストで実行設定された cmd を実行するのは、ハブの役目そのもの(認証と上の Host・Origin の確認で守る)
ダウンロードの URL・宛先(SSRF)http / https だけ。接続前に名前を引いて、内部のアドレス(loopback・LAN・リンクローカル・IPv4 を含む IPv6)は断る。リダイレクトのたびに、同じ確認をして、https から http への転送も断る。allow_private_downloads で、許可に切り替えできる名前の引き直しで、アドレスが変わる攻撃(DNS の再解決)は、完全には防げない
トークンの送信先HF / Civitai のトークンは、正規のドメイン(とそのサブドメイン)への https にだけ付ける(evilhf.co のような似た名前には付けない)。ホストが変わるリダイレクトでは外す—
保存先の上書き・リンク同じ保存先のジョブは、重ねて登録できない。完成時も、既存のファイルは上書きしない。.part がリンクなら書き込まない(O_NOFOLLOW)。モデルセットは、リンクを解決した先が、モデル置き場の中のものだけを表示し、表示用フォルダ内のリンクは、辿らずに消す—
リクエストの上限本文は 4 MiB まで(超えると 413、負の値は 400)。接続は 30 秒で切る。待機中のダウンロードは 500 件まで。サイズ不明の転送も、空き容量を確認する。ログは、末尾だけを読む同時接続数の上限はない(LAN の信頼が前提)
状態ファイルの同時書き込み設定・セット・秘密情報は、読み込みから書き込みまでを、1つのロックで保護。書き込みは、固有名の一時ファイルから置き換え。secrets.json は、毎回 600 で作り直す(フォルダは 700)。RUN の更新もロック。PID の使い回しは、開始時刻(/proc)で見分けるポート経由で見つけた外部のプロセスの停止は、仕様どおり(同一性は確認できない)
パスの逃げダウンロードは safe_dest、セットは _clean_files で、モデル置き場の外を拒否。静的ファイルは web/ の外に出ない(テスト済み)。拡張子も制限cmd と server_dir は、利用者が自由に指定できる(設計上、必要)
秘密情報secrets.json は権限 600、フォルダはリポジトリの外。API はキーを返さない(生成直後のみ)起動したプロセスの環境変数には、キーが入る(OS の標準的な範囲)
ファイルの削除ハブは、モデルを削除しない(コマンドを表示するだけ)—

指摘対応
C1 認証なしの LAN 公開で、任意のコマンドを実行できる設計どおり(対応しない)。認証は任意の補足機能で、信頼できる LAN が前提。README と §12 に明記

M4 読み込み〜書き込みにロックがない解消(設定・セット・秘密情報・RUN)。CFG の直接共有など、構造の整理は今後の候補

M11 secrets.json の権限が戻らない解消。毎回 600 で作り直す
